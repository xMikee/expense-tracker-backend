# JWT Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `POST /auth/login` endpoint (email + password → JWT) as a second, additive
auth method alongside the existing `x-api-key` header, per
`docs/superpowers/specs/2026-08-03-jwt-login-design.md`.

**Architecture:** New `AuthModule` (`AuthService` + `AuthController`) wraps `@nestjs/jwt`.
`AuthMiddleware` is extended to accept `Authorization: Bearer <jwt>` in addition to the
existing `x-api-key` lookup, trying JWT first. `User` gets a new `password` column (bcrypt
hash). `CreateUserDto`/`UsersService` hash the password on user creation. A one-off script
sets a password for the one existing user.

**Tech Stack:** NestJS 10, Prisma 5, `@nestjs/jwt`, `bcrypt`, `class-validator`.

## Global Constraints

- Do not remove or change behavior of the existing `x-api-key` flow — every current client
  (Telegram bot, scripts) must keep working unchanged.
- JWT expiry: `7d` (spec decision, no refresh tokens).
- Login failure (bad email OR bad password) must return the **same** generic 401 message —
  do not leak whether the email exists.
- Never include the `password` hash field in any API response body.
- This repo has **no test framework configured** (no jest, no `.spec.ts` files anywhere). Do
  not introduce one for this feature — follow the codebase's existing convention of manual
  verification via `curl`/`npm run build` instead of adding Jest. (This deviates from the
  spec's "Unit test AuthService.validateUser" line; manual curl verification replaces it,
  documented here so it isn't a silent gap.)
- The worktree this plan runs in has no `node_modules` and no `.env` yet (both are
  gitignored and not present in a fresh `git worktree add`). Task 1 sets both up.

```ts
import { Injectable } from '@nestjs/common';
import { randomBytes } from 'crypto';
import * as bcrypt from 'bcrypt';
import { PrismaService } from '../prisma/prisma.service';
import { CreateUserDto } from './dto/create-user.dto';

@Injectable()
export class UsersService {
  constructor(private readonly prisma: PrismaService) {}

  async create(dto: CreateUserDto) {
    const apiKey = randomBytes(24).toString('hex');
    const password = await bcrypt.hash(dto.password, 10);
    const user = await this.prisma.user.create({
      data: {
        email: dto.email,
        telegramChatId: dto.telegramChatId,
        apiKey,
        password,
      },
    });
    const { password: _omit, ...safeUser } = user;
    return safeUser;
  }
}
```

```js
// One-off: sets a bcrypt-hashed password for a user identified by email.
// Usage: node scripts/set-initial-password.js <email> <plaintext-password>
const { PrismaClient } = require('@prisma/client');
const bcrypt = require('bcrypt');

async function main() {
  const [, , email, plainPassword] = process.argv;
  if (!email || !plainPassword) {
    console.error('Usage: node scripts/set-initial-password.js <email> <password>');
    process.exit(1);
  }
  const prisma = new PrismaClient();
  const hash = await bcrypt.hash(plainPassword, 10);
  const user = await prisma.user.update({
    where: { email },
    data: { password: hash },
  });
  console.log(`Password impostata per ${user.email}`);
  await prisma.$disconnect();
}

main();
```

- [ ] **Step 3: Create `AuthService`**

Create `src/auth/auth.service.ts`:

```ts
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';
import { PrismaService } from '../prisma/prisma.service';

@Injectable()
export class AuthService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly jwt: JwtService,
  ) {}

  async login(email: string, password: string) {
    const user = await this.prisma.user.findUnique({ where: { email } });
    const passwordMatches = user ? await bcrypt.compare(password, user.password) : false;

    if (!user || !passwordMatches) {
      throw new UnauthorizedException('Credenziali non valide');
    }

    const accessToken = await this.jwt.signAsync({ sub: user.id, email: user.email });
    return { accessToken };
  }
}
```

Note: `bcrypt.compare` still runs (against a throwaway value) even when `user` is `null`,
would be nice for timing-safety, but is deliberately skipped here — YAGNI for a personal
single-user tool. Do not add it.

```ts
import { AuthController } from './auth.controller';
```

### Task 5: `AuthMiddleware` accepts JWT or apiKey

**Files:**
- Modify: `src/auth/auth.middleware.ts`

**Interfaces:**
- Consumes: `JwtService.verifyAsync` (from `@nestjs/jwt`, already configured in
  `AuthModule`), payload shape `{ sub: string; email: string }` from Task 4.
- Produces: `req.userId` set the same way regardless of which auth method was used — no
  other module needs to change.

- [ ] **Step 1: Rewrite the middleware**

Replace the contents of `src/auth/auth.middleware.ts`:

```ts
import { Injectable, NestMiddleware, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import { PrismaService } from '../prisma/prisma.service';

@Injectable()
export class AuthMiddleware implements NestMiddleware {
  constructor(
    private readonly prisma: PrismaService,
    private readonly jwt: JwtService,
  ) {}

  async use(req: any, res: any, next: () => void) {
    const authHeader = req.headers['authorization'];

    if (authHeader?.startsWith('Bearer ')) {
      const token = authHeader.slice('Bearer '.length);
      try {
        const payload = await this.jwt.verifyAsync(token);
        req.userId = payload.sub;
        return next();
      } catch {
        throw new UnauthorizedException('Token non valido o scaduto');
      }
    }

    const apiKey = req.headers['x-api-key'];
    if (!apiKey) {
      throw new UnauthorizedException('Header x-api-key o Authorization mancante');
    }

    const user = await this.prisma.user.findUnique({ where: { apiKey } });
    if (!user) {
      throw new UnauthorizedException('API key non valida');
    }

    req.userId = user.id;
    next();
  }
}
```

Key behavior preserved from the spec: if `Authorization: Bearer` is present but invalid,
fail immediately with 401 — do not fall back to checking `x-api-key`.
